## 岗位画像
- **典型职级**：初级（1-3 年）/ 中级（3-5 年）/ 高级（5+ 年）
- **核心能力**：把一个业务请求安全、稳定、高效地变成持久化状态变更
- **面试者画像**：通常由 leader + 资深工程师 2 轮技术面 + 1 轮系统设计
- **常见误判**：候选人能背 Redis 命令但说不清「为什么用 Redis 而不是 MySQL」——这种背诵型必须深挖

## 考察维度

### 1. 存储层（权重 30%）
- 索引：B+ 树结构、覆盖索引、最左前缀、回表、索引失效场景
- 事务：ACID、隔离级别（RU/RC/RR/Serializable）、MVCC、幻读
- 锁：行锁/表锁/间隙锁、死锁排查、乐观锁 vs 悲观锁
- 分库分表：拆分维度、跨库事务、分布式 ID

### 2. 缓存层（权重 20%）
- 缓存模式：Cache-Aside / Read-Through / Write-Behind
- 一致性：双写不一致、延迟双删、Canal/binlog 订阅
- 三大问题：穿透（布隆过滤器）、击穿（互斥锁/逻辑过期）、雪崩（随机过期/多级缓存）
- 数据结构选型：String / Hash / ZSet / Stream 各自的场景

### 3. 并发与一致性（权重 20%）
- 分布式锁：Redis SETNX、Redlock 争议、ZooKeeper 临时节点对比
- 幂等：唯一索引、token 机制、状态机
- 分布式事务：2PC / TCC / Saga / 本地消息表 / 事务消息
- CAP 与 BASE：能讲清取舍而非背定义

### 4. 高可用与容错（权重 20%）
- 限流：令牌桶 / 漏桶 / 滑动窗口
- 熔断降级：Hystrix / Sentinel 模型、半开态
- 异步化：MQ 削峰、最终一致性、消息重复消费
- 监控：四个黄金信号（延迟、流量、错误、饱和度）

### 5. 工程素养（权重 10%）
- 接口设计：REST 语义、幂等性、版本管理
- 可观测：日志/Trace/Metrics 三件套
- 部署：滚动/蓝绿/灰度

## 出题节奏（建议 60 分钟）
1. **开胃（5 min）**：让候选人讲一个简历最深的项目，找深挖锚点
2. **基础（15 min）**：1 道索引 + 1 道事务，确认基本功
3. **缓存深挖（15 min）**：从一致性入手，逼到 binlog 订阅或延迟双删
4. **并发场景（15 min）**：分布式锁场景题，看会不会想到「锁过期但任务没跑完」
5. **系统题（10 min）**：限流器/秒杀/消息可靠投递三选一

## 追问树

### 答得好 → 加深一层
- 「这个方案在 QPS 10w 下瓶颈在哪？」
- 「如果 Redis 宕机这套方案怎么降级？」
- 「这道题如果不让用 Redis 你怎么做？」
- 「你刚才说的 Redlock，反对方（Martin Kleppmann）的论点是什么？」

### 答得卡 → 给提示或换角度
- 「先想读写比例？读多还是写多？」
- 「我们退一步，单机版你怎么做？」
- 「我换个问法：如果一个用户在两台机器同时提交，会发生什么？」

### 答得含糊 → 要求举具体例子
- 「你说『大概率会有问题』，具体哪一行代码会出问题？」
- 「能画一下时序图吗？」
- 「上一家公司你具体怎么做的？给个数字：QPS、延迟、机器数」
- 「你简历写『精通 MySQL 调优』，给我看一个你真实优化过的慢 SQL」

## 典型陷阱与红旗信号

| 信号 | 含义 |
|---|---|
| **overclaim** | 简历写「精通 Redis」但答不出 SETNX 的原子性 → 标记诚信风险 |
| **背书式** | 一问 MVCC 就开始背 undo log 链路但不知道为什么需要 → 标记死记硬背 |
| **八股套话** | 一开口就「CAP 理论…」却分不清 CP/AP 系统举例 → 标记缺乏实战 |
| **跳跃式** | 答不到点上反复绕，绕到擅长的方向 → 警惕，必须拉回原问题 |
| **不懂装懂** | 「这个我们公司也用」但具体细节支吾 → 让他画架构图 |

## 评分 rubric（每维度 1-5 分）

| 分 | 描述 |
|---|---|
| 1 | 完全不懂或概念错误 |
| 2 | 知道名词但讲不清原理 |
| 3 | 能讲清原理，能答课本知识 |
| 4 | 能结合实际场景做权衡，有踩坑经验 |
| 5 | 能讲清行业不同方案的边界、有源码级理解、能反推设计动机 |

**通过线**：综合 3.0+ 算合格；高级岗需要 3.5+ 且至少一个维度 4+。

## 与简历交叉验证清单
- 简历写「负责 X 系统重构」→ 让他画当时的架构 → 让他对比重构前后
- 简历写「QPS 提升 10 倍」→ 追问基线数字、瓶颈定位手段、优化项
- 简历写「精通 Y」→ 直接问 Y 最反直觉的一个点（如 MySQL 的间隙锁）
- 简历写「主导」→ 追问团队规模、决策过程、阻力如何处理
