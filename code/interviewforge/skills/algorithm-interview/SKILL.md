## 岗位画像
- **典型场景**：大厂校招/社招的一面或二面、量化/搜推岗的笔试 + 现场白板
- **核心能力**：把一个有约束的问题正确建模 + 选对数据结构 + 写出无 bug 代码
- **考察价值**：不是考记题，是考三件事——**问清楚问题、找出关键洞察、把想法变成可运行代码**
- **常见误判**：背过原题秒出最优解 → 必须换约束验证是否真理解

## 考察维度

### 1. 问题澄清（权重 15%）
- 主动确认输入范围（n 多大？数据范围？是否有负数？）
- 询问边界（空输入？单元素？重复元素？溢出？）
- 询问输出形式（任一解 / 所有解 / 计数 / 最优值）
- 与面试官确认假设而非自己脑补

### 2. 思路推导（权重 30%）
- **暴力解优先**：先讲 O(n²)/O(2ⁿ) 暴力，再优化——展示思维过程比直接给最优重要
- **发现重复子问题** → DP / 记忆化
- **发现单调性** → 二分 / 双指针 / 单调队列
- **发现局部最优 = 全局最优** → 贪心（要能证明）
- **发现状态转移** → 状态机 DP
- **发现连通/合并** → 并查集

### 3. 数据结构选型（权重 20%）
- 数组 vs 链表 vs 哈希 的时空权衡
- 堆（Top K / 中位数）、单调栈（NGE）、Trie（前缀）、并查集（连通性）、线段树/树状数组（区间）
- 选错数据结构是 mid-junior 的最大区分点

### 4. 复杂度分析（权重 15%）
- 主动报时间和空间复杂度
- 能说清为什么是这个复杂度（递归树 / 主定理 / 摊还分析）
- 能给出复杂度下界（信息论 / 比较模型）

### 5. 编码与调试（权重 20%）
- 命名清晰、边界完整（左闭右开/右闭统一）
- 不会被 off-by-one / 整型溢出 / 空指针绊倒
- 写完会主动跑一两个小用例 dry-run
- 代码风格能反映工程素养

## 出题节奏（建议 45-60 分钟）
1. **热身（5 min）**：一道高频简单题（反转链表/两数之和）建立信心
2. **主菜（25 min）**：一道中等偏难（DP/图/字符串），看完整思维过程
3. **追加（10 min）**：换约束追加（数据规模 ×1000？数据流式？带删除？）
4. **白板/电脑（剩余）**：把核心代码写完整并 dry-run

## 追问树

### 思路对 → 引导优化与边界
- 「能再优化一个数量级吗？空间能从 O(n) 降到 O(1) 吗？」
- 「如果 n = 10⁹ 装不下内存怎么办？」（引向外排/流式/概率算法）
- 「数据是流式来的，不能预读，你怎么改？」
- 「如果允许重复值/负数/超大整数，你的解还成立吗？」

### 卡住 → 小提示，递进式
- 第一档：「先想暴力，能 AC 才有优化空间」
- 第二档：「这个问题里哪两个状态是重叠的？」
- 第三档（明确给数据结构）：「试试单调栈/Trie/并查集」
- 不要直接给答案——给完答案就失去信号了

### 只会暴力 → 引导发现优化点
- 「你这个暴力里哪一步最重复？」
- 「这个子问题在 n 次循环里算了多少次？」
- 「假设我把这个中间结果存下来，能省多少？」

### 一上来就是最优解 → 怀疑背题，换约束验证
- 「能讲一下你是怎么想到这个解法的？」
- 「把数据从一维改成二维，你的解还能用吗？」
- 「换约束：要求在线（数据动态加入），你怎么改？」

## 典型陷阱与红旗信号

| 信号 | 含义 |
|---|---|
| **背题型** | 一上来就给最优解，让讲思路推导就支吾 → 换约束验证 |
| **不澄清就写** | 不问数据范围/边界直接动手 → 工程习惯差 |
| **复杂度说错** | 把 O(n log n) 说成 O(n) → 基础不牢 |
| **边界总错** | 反复被空数组/单元素 hack → 编码不严谨 |
| **不肯写代码** | 只讲思路不动笔，「这个我会但懒得写」→ 实战能力存疑 |
| **不会 dry-run** | 写完不会自己跑用例 → 缺乏 debug 直觉 |

## 评分 rubric（每维度 1-5 分）

| 分 | 思路 | 编码 |
|---|---|---|
| 1 | 完全没思路 | 写不出可运行代码 |
| 2 | 只能想到暴力 | 有 bug 但能修 |
| 3 | 提示后能想到优化 | 一次写对简单题 |
| 4 | 独立想到最优解并能证明 | 一次写对中等题，边界全 |
| 5 | 给出多解并比较 trade-off，能讲清复杂度下界 | 代码可读、命名好、风格工程化 |

**通过线**：综合 3.0+；竞赛背景岗位至少一维 5。
