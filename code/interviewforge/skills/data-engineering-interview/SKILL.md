## 岗位画像
- **典型职级**：初级（1-3 年，能写 SQL/调度任务）/ 中级（建模 + 性能优化）/ 高级（数仓架构 + 治理 + 平台）
- **核心能力**：把业务定义 → 可信、可用、可追溯的数据资产 + 满足查询性能 SLA
- **核心区别于后端**：后端关注「事务+在线请求」，数据工程关注「批量+维度建模+口径一致性」

## 考察维度

### 1. SQL 与维度建模（权重 30%）
- **SQL 进阶**：窗口函数（row_number/lag/lead/累计指标）、CTE、行列转换、复杂关联
- **建模**：Kimball 维度建模（事实表/维度表/雪花/星型）、Inmon 范式建模
- **慢变维**：SCD Type 1/2/3/6 各自场景
- **分层**：ODS / DWD / DWS / ADS 分层意义、数据流向
- **指标口径**：原子指标 / 派生指标 / 复合指标，统一口径管理

### 2. 计算引擎（权重 25%）
- **Spark**：RDD/DataFrame/Dataset、Shuffle 原理、宽窄依赖、AQE、数据倾斜处理
- **Flink**：流处理语义（at-least-once/exactly-once）、Checkpoint、Watermark、State 后端
- **Hive**：MapReduce 引擎、向量化、动态分区、小文件治理
- **批流一体**：Lambda vs Kappa 架构、湖仓（Iceberg/Hudi/Paimon）

### 3. 存储与查询（权重 20%）
- **HDFS/对象存储**：副本、纠删码、小文件
- **OLAP**：ClickHouse / Doris / StarRocks / Druid 各自适用场景
- **列式存储**：Parquet / ORC 编码（RLE / Dictionary）、谓词下推
- **HBase**：RowKey 设计、热点、Region 切分
- **MQ**：Kafka 分区策略、消费位移、Exactly Once Semantics

### 4. 数据治理（权重 15%）
- **数据质量**：完整性 / 准确性 / 一致性 / 及时性 / 唯一性 五大维度，怎么监控
- **元数据**：血缘（lineage）、影响分析
- **数据安全**：分级分类、脱敏、最小权限
- **成本治理**：冷热分离、过期清理、按需计算

### 5. 工程素养（权重 10%）
- 调度系统：Airflow / DolphinScheduler / 海豚调度
- 数据质量监控：DQC 工具
- 数据开发流程：需求 → 建模 → 开发 → 测试 → 上线 → 监控

## 高频考题与切入

| 题目 | 关键深挖点 |
|---|---|
| **统计每个用户最近 N 天 DAU** | 窗口函数 + 累积指标计算 |
| **Spark 数据倾斜处理** | 加盐 / 两阶段聚合 / Map Join / Skew Hint |
| **Flink 实时数仓** | 双流 Join、维表 Join（异步 IO/广播）、Watermark 乱序 |
| **设计一个埋点日志数仓** | 分层 + 建模 + 计算 + OLAP 选型全流程 |
| **HBase RowKey 设计** | 反转 / 加盐 / 时间散列防热点 |
| **小文件治理** | 合并 / CombineFileInputFormat / Iceberg 自动 compact |
| **指标口径不一致排查** | 口径管理流程、血缘追踪 |

## 追问树

### 答得好 → 加压
- 「这套方案在万亿行数据下 Shuffle 怎么撑？」
- 「Flink 升级到 Kappa，离线那套报表怎么迁？」
- 「指标口径变了，历史数据怎么回溯？成本多少？」

### 答得卡 → 给抓手
- 「先讲讲你之前做过的最大的表多大？怎么算的？」
- 「不考虑实时，纯离线你怎么实现？」

### 答得套话 → 要数字
- 「你说『性能差不多』，QPS / 延迟 / 数据量给个数字」
- 「降本 30%，原本多少钱、降到多少？降在哪？」

## 红旗信号

| 信号 | 含义 |
|---|---|
| **只会拉数 SQL** | 不懂建模 → 初级以上不达标 |
| **背 Spark 论文** | 讲得头头是道但没真正调过 Shuffle |
| **分层混乱** | DWD 跨调 ADS、ADS 直查 ODS → 数仓素养差 |
| **口径靠口口相传** | 没指标管理 → 治理能力差 |
| **Flink 只懂 API** | 不懂 State / Watermark / Checkpoint 内部 |
| **避谈数据质量** | 没踩过事故 → 经验存疑 |

## 评分 rubric（每维度 1-5 分）

| 分 | 描述 |
|---|---|
| 1 | 概念错或不会写 SQL |
| 2 | 会基础 SQL + 简单调度，但不会建模 |
| 3 | 会建模、能讲清 ODS-ADS 数据流、能用 Spark/Flink |
| 4 | 能定位 Shuffle / 数据倾斜 / 资源瓶颈，能讲清治理框架 |
| 5 | 能讲清行业不同湖仓方案、能给出建模与平台架构演进路径 |

**通过线**：中级 3.0+；高级 3.5+ 且建模或治理至少一项 4+。
